# X2 robot operations

Verified 2026-07-28. PC2 = Jetson Orin NX on the robot. Laptop and PC2 on
the robogym WiFi. **PC2's DHCP address moves** — find it by MAC
`bc:d2:2c:60:c8:c7` (hostname `agi.lan`); last known `192.168.86.32`.
Keep `~/.x2/env.wifi` on THIS laptop pointing at it, with `LAPTOP_HOST`
set to THIS laptop's own robogym IP (it is machine-local, not in git).

First-time setup on a new laptop:

```bash
mkdir -p ~/.x2
ip -4 addr show | grep "192.168.86."        # this laptop's robogym IP
# PC2 is DHCP; if .32 doesn't ping, sweep + match its MAC:
#   for i in $(seq 1 254); do ping -c1 -W1 192.168.86.$i >/dev/null 2>&1 & done; wait
#   arp -a | grep -i bc:d2:2c
cat > ~/.x2/env.wifi <<'EOF'
export PC2_HOST=192.168.86.32     # PC2 Jetson (MAC bc:d2:2c:60:c8:c7)
export LAPTOP_HOST=192.168.86.XX  # THIS laptop's robogym IP
export PC1_HOST=10.0.1.40
EOF
```

`LAPTOP_HOST` must be this machine's own IP: the PC2 watchdog subscribes
back to it for the pose stream in tethered mode. Wrong value => the
deploy's wire-probe fails at startup (safe, but confusing).

## Safety invariants (non-negotiable)

- NO ssh/commands to PC2/PC3 without explicit per-user-action approval.
  Ignition-class actions are NEVER run remotely by Claude.
- Never kill `x2_deploy` or `x2_pose_watchdog` while SONIC is live —
  the deploy runs `--disable-pose-ref-watchdog` and trusts the watchdog.
- Never kill `pc2_kplanner` mid-motion under the RITUAL watchdog: its
  fallback ladder is 0.05 s hold / 0.15 s blend — a live robot gets
  snapped to idle pose in 150 ms (caused a fall 2026-07-28). The
  tethered/daemons watchdog uses 5 s / 3 s and tolerates upstream loss.
- The pose wire carries joint positions + root ORIENTATION only (no root
  xy) — reason about reference discontinuities accordingly.
- MC stand-mode refusals while the robot is down/fallen are expected and
  safe (posture detector) — never fight or retry them.

## Gamepad ritual (untethered demo)

Pad daemon (`x2-pad-autopair.service`) is always on. Chord: hold
L1+L2+R1+R2 3 s (haptic countdown) then Y. Ignition chain:
plumbing daemons → pose-stream gate on :5558 → deploy via the
PC2-resident `start_x2_deploy_ritual.sh` (`--no-confirm` baked in;
default tuning `walking_soft_kp.yaml`; overrides via env
`X2_RITUAL_MODEL` / `X2_RITUAL_TUNING`). The rituals must NEVER launch
`log/start_x2_deploy.sh` — that body is regenerated by every laptop
daemons start with that session's flags.

Obstacle guard: scan clamp holds forward/lateral inside 1.6 m and the
planner LATCHES. Yaw always survives — turn away until "path clear",
then release + re-engage the deadman to reset the latch.

## VR teleop / record (VLA datasets)

Tethered topology: laptop runs VR manager + planner + recorder; PC2 keeps
deploy + watchdog + bridges. Prerequisites on the operating laptop:
repo `asimov` branch pulled, `.venv` with pyzmq+msgpack, Quest 3 on the
robot AP.

```bash
source ~/.x2/env.wifi   # PC2_HOST=<current PC2 ip>, LAPTOP_HOST=<this laptop's ip>

# 1. PC2 stack, tethered topology, proven tuning:
#    (flag is --tuning, NOT --tuning-config -- that's deploy_x2.sh's inner
#     flag; bare filename resolves under configs/real_deploy_tuning/ and
#     is JIT-rsynced from this laptop to PC2 at start)
./gear_sonic_deploy/scripts/x2_pc2_daemons.sh start \
    --pc2-host "$PC2_HOST" --tuning walking_soft_kp.yaml
# attach the deploy pane and answer the y/N safety gate at the keyboard

# 2. VR stack + recorder (auto-serves the PC2 camera bridge, then HARD
#    GATES on real frames from head_front + stereo pair before recording):
./gear_sonic/scripts/run_x2_quest3_planner_stack.sh --duration 0 \
    --pc2-host "$PC2_HOST" --with-record \
    --output-dir ~/datasets/x2_vla_$(date +%Y%m%d) \
    --task "<task description>" --head-cameras
```

Engage VR with A+B+X+Y in the headset. Episodes land as LeRobot v2.1
with `observation.images.{head_front,stereo_left,stereo_right}`.

Camera gate failures print the exact fix per stream:
- `head_front` (Orbbec, the stream VLA training needs most): the
  `orbbec_camera` em-app must be RUNNING on PC2.
- `stereo_left/right` (IMX900 Argus boot race):
  `./gear_sonic_deploy/scripts/x2_pc2_cameras.sh restart-hal` and retry.
Standalone probe: `gear_sonic/scripts/probe_x2_head_cameras.py --host $PC2_HOST`.

Arbitration rule (user directive): when VR is engaged, VR owns the WHOLE
robot; the pad is out of the loop. Never build/assume a pad-locomotion +
VR-arms split.

## Teardown

```bash
# order matters: disengage VR → Ctrl-C the laptop stack → then:
./gear_sonic_deploy/scripts/x2_pc2_daemons.sh stop --pc2-host "$PC2_HOST"
# verify: ssh run@$PC2_HOST 'tmux ls 2>/dev/null || echo all down'
```

With a fallen robot: let the stop's MC hand-back fail (robot stays
passive), recover physically, then normal MC bring-up.
