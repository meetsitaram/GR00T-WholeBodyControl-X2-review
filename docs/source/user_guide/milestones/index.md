| 2026-06-07 | Calibration palm-direction lock + multi-pose wrist offset (v1) | **Real X2 + sim**, Quest 3 stack | Lock palm direction in every calibration prompt (printed + TTS) so the arms-down `wrist_alignment_quat` reference is reproducible. New `fit.<side>.op_quat_offset_rpy_deg` field on `ArmFit` persists a per-operator wrist-quat offset in the calibration YAML; `VRArmTeleopCalibrated` resolves it three-tier (CLI > YAML > identity), so every launcher (kinematic teleop, dataset recording, VLA bridge) picks it up automatically. Recommended values for this operator (LEFT `-5.7 +1.8 -6.0`, RIGHT `+0.3 +4.4 +10.4`) derived from a Markley quaternion LS average over `arms_down + t_pose + arms_forward` (namaste excluded). | 2026-06-10 | Manual takeover during VLA inference | **Real X2 + SONIC + N1.7**, Quest 3 stack | Operator can grab the wire from a stuck VLA via VR teleop without restarting the bridge. Two-part change: (a) `x2_pose_proxy.py` gains optional dual-source arbitration (`--override-port`) and an edge-triggered control PUB (`--vla-control-port`) — override frames win whenever fresh, debounced via `--override-stale-ms`. (b) `live_vla_publish_motion_token.py` gains a `vla_control` SUB and a `_VlaControlSignal` cold-restart pathway — on the override_released edge the bridge clears ramp / LPF / chunk-blend state, pins a chunk-id baseline (drops pre-override chunks), and hold-publishes the operator's measured pose for `--vla-cold-restart-hold-ticks` (default 25 = 500 ms) so the proxy's HOLD -> LIVE handoff doesn't see a step change. Quest 3 manager is **untouched** — engagement is implicit (whatever publishes on the override port wins). All new code paths gated on positive port numbers; defaults disabled, byte-for-byte unchanged on existing single-source runs. |
| 2026-06-08 | Pose-proxy fallback ladder: freeze arms on upstream stall | **Real X2 + SONIC + VR teleop** | Replaces the PC2 pose proxy's binary `LIVE/IDLE` fallback with a staged `LIVE -> HOLD -> BLEND -> IDLE_CLIP` ladder so a WiFi blip / laptop GC pause / Cursor reload during teleop no longer slams the arms into default-stand. HOLD (default 10 s) re-publishes the LAST forwarded upstream BYTES verbatim -> deploy sees `jvel=0`, zero kinematic surprise. BLEND (default 3 s) lerps `joint_pos_mj` toward the baked idle clip so the eventual fall-back is a smooth glide rather than a step. New `--idle-mode {blend,hold-last,idle-stand}` CLI knob (default `blend`); `idle-stand` reproduces pre-2026-06-08 behaviour as a regression escape. C++ deploy untouched. 20 new unit tests; 38/38 proxy tests passing. |
| 2026-06-10 | Closed-loop tracking feedback on the VLA wire | **Real X2 + SONIC + N1.7 VLA bridge** | Adds optional per-arm-joint closed-loop tracking feedback to the VLA bridge wire step cap to stop the open-loop drift / battery-sag / motor-temp oscillations that the v3 static defaults (LPF / blend / scalar step-cap) couldn't reliably suppress. New `_apply_tracking_feedback` helper observes `x2_debug`'s measured arm-joint positions + velocities each tick and per-joint-throttles the wire delta via two composed laws (position backoff on `|target - measured|`, velocity cap on `|measured_dq|`). New `_clamp_vector_step_per_joint` clamps each joint independently (vs scalar variant's whole-vector scale) so only the lagging joint slows down. Arms-only joint mask (legs/waist/head pass through); falls back to the scalar clamp when proprio is stale. **Step 1 rollout: default OFF**, opt in via `--vla-tracking-feedback` or `VLA_TRACKING_FEEDBACK=1`; v3 defaults stay in place so feedback is additive belt-and-suspenders. Step 2 (separate commit) will flip default ON and relax v3 statics. New `tf_throttle=N/14` field in pub-tick log. 30 new unit tests + 5 new launcher CLI tests; 25/25 sim-proxy + 30/30 feedback tests green. |
| 2026-06-11 | Pose pipeline split (`x2_pose_mux` + `x2_pose_watchdog`) | **Real X2 + SONIC + Quest 3 stack** | Refactor of the 2026-06-10 manual-takeover plumbing. Splits the single `x2_pose_proxy.py` into a laptop-side `x2_pose_mux` (dual-source arbitration + engagement ramp + `vla_control` edges) and a slim PC2-side `x2_pose_watchdog` (fallback ladder only, renamed from `x2_pose_proxy.py`). Same `bridge → mux → watchdog → deploy` topology in sim and real now — sim spawns the watchdog locally on loopback instead of crossing wifi. Shared library `gear_sonic/utils/pose_pipeline/` (`wire.py`, `clamp.py`, `fallback.py`, `arbitrate.py`) factors out the common code. New `--enable-takeover` master switch in `run_x2_vla_runtime.sh`; new `--takeover` convenience flag in `run_x2_quest3_planner_stack.sh`. Legacy `POSE_PROXY_OVERRIDE_*` / `POSE_PROXY_TELEOP_*` / `POSE_PROXY_CONTROL_*` env vars on PC2 now hard-fail with a migration pointer; legacy CLI flags on the watchdog also fail closed. Bridge `--pub-port` automatically flips to an internal `5570` when `--enable-takeover` is set so the mux can bind the canonical `5556`. **No behaviour change for autonomous-only runs**: bytes still flow bridge → PC2 watchdog → deploy unchanged. 88/88 pose-pipeline tests + 28/28 launcher tests green. |
| 2026-06-22 | Dataset replay v5 future-window wire + single-shell launcher | **Sim + real X2**, deploy + SONIC | Fixes the long-standing "replay's fingers move but the body stays in `idle_stand`" bug. Root cause: the C++ deploy ignores `motion_token` on the wire and re-tokenizes from `joint_pos_mj_future`; the replay was publishing only the v4 envelope so the deploy back-filled the future window with the trained `default_angles` stand pose. Promotes [`replay_x2_dataset.py`](../../../gear_sonic/scripts/replay_x2_dataset.py) to v5 by adding `joint_pos_mj_future` + `root_quat_xyzw_future` + `joint_vel_mj_future` + `frame_index_future` + `future_dt_s` (9 slots @ 0.1 s spacing, built from the parquet's `body_q` at offsets `f+5..f+45`, tail-tiled past episode end). New [`run_x2_replay_stack.sh`](../../../gear_sonic/scripts/run_x2_replay_stack.sh) wrapper mirrors the [`run_x2_vla_runtime.sh`](../../../gear_sonic/scripts/run_x2_vla_runtime.sh) pattern: single-shell deploy + replay + reverse-order trap cleanup, with `--no-deploy` / `--pc2-host` / `--with-rerun` modes. The `--with-rerun` flag spawns [`view_x2_recorded_dataset.sh`](../../../gear_sonic/scripts/view_x2_recorded_dataset.sh) alongside the live deploy so the operator can eyeball the recorded MP4s + scalar timeline against the live sim/robot. Default `--sim-profile handoff` (not `parity`, which needs a baked RSI PKL replay doesn't have). 13/13 new tests pass (future-window indexing, tail-tile, velocity finite-diff, v5 schema, byte-for-byte pack/unpack roundtrip). |
| 2026-06-23 | Pose PUB LAN isolation (sim runs can't reach PC2) | **Sim + real X2**, all launchers | Plugs a silent safety leak where sim-mode runs of `run_x2_vla_runtime.sh` / `run_x2_replay_stack.sh` could unintentionally drive the real robot. PC2's `x2_pose_proxy` daemon is always-on by design (operator never SSHes in to stop it) and SUBs `<LAPTOP_IP>:5556` over wifi. ZMQ SUBs connect out, so whenever the laptop bound the pose PUB on `*:5556` (hardcoded everywhere), PC2 attached and the real robot executed the sim wire. The wrapper's `SIM_MODE=1` / `PC2_HOST=""` was internal state that never propagated to the bind argument. Fix: new `PUB_BIND_HOST` env var derived from `SIM_MODE` (runtime) / `PC2_HOST` (replay) — sim → `127.0.0.1`, real → `*`. Plumbed into the bridge, mux, recorder, and replay PUBs. New banner line in both wrappers echoes the resolved bind with LAN-isolation vs LAN-visible suffix. `:=` form so an explicit `PUB_BIND_HOST=*` env override still wins for cross-host sim debugging. Restores the invariant: `--pc2-host` is the single source of truth for whether the laptop's pose wire reaches the real robot. 10/10 new tests + 29/29 existing launcher tests green. |
| 2026-06-23 | VLA bridge holds last-good live `root_quat` across `x2_debug` stalls | **Real X2 + SONIC + N1.7 VLA bridge** | Fixes a regression of the [2026-06-07 heading-stability symptom](2026-06-07_vla_bridge_heading_stability_and_head_lock.md): robot snaps back to spawn heading on first VLA start and on every manual nudge, even though `x2_debug` is being subscribed to. Root cause: the bridge's yaw-rebase + waist_yaw pin were gated on `deploy_fresh` (1 s freshness); on the `not deploy_fresh` branch the wire shipped the baked-identity quat from the idle clip (= world +X), and the C++ deploy commanded the body back to spawn heading on every >1 s wifi blip / GPU stall. Quest3 / VR teleop is structurally protected from this because the kplanner uses "hold last good, overwrite when fresh" semantics on `current_root_wxyz` (`x2_kplanner.py:2816-2821`). Lift that pattern into the bridge: cache `last_known_base_quat_wxyz` + `last_known_body_q_mj`, resolve the source via `_resolve_wire_rebase_source` each tick (`live` / `cached` / `none`), prefer the live snapshot, fall back to the cache, only fall back to identity if no `x2_debug` has ever arrived. A stale cached yaw is strictly better than identity. Promote the one-shot `yaw_rebase_logged` flag to a state-transition emitter (`_log_rebase_source_transition`) so ACTIVE / STALE / RECOVERED edges are each logged once — no per-tick spam, no silent mid-session regressions. The recorder's identical-shape `_compute_idle_root_quat_xyzw` is documented as a dormant bug not fixed this turn (only triggers during recorder-generated idle frames, which haven't bitten in a long time). 25/25 new tests green. **✅ Real-robot validated same day.** |
